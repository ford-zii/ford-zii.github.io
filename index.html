Boss battlesบอสที่ปราบแล้ว

Real production fights. Open a card to see how the root cause was found. Company specifics stay sealed.

  • The Midnight Timezone Wraithวิญญาณเขตเวลาเที่ยงคืน Defeatedปราบแล้ว
    Symptomอาการ
    Bills created near midnight got the wrong business date.บิลที่สร้างใกล้เที่ยงคืนได้วันที่ทางบัญชีผิด
    Root causeต้นเหตุ
    Two services read timezone-less datetimes differently.สอง service อ่าน datetime ที่ไม่มี timezone ไม่เหมือนกัน
    Fixวิธีแก้
    Kept the accounting rule, aligned both publisher and parser to Bangkok time, added a test right at the boundary.คงกฎบัญชีไว้ ปรับทั้งฝั่งส่งและฝั่ง parse ให้เป็นเวลากรุงเทพ เพิ่มเทสต์ตรงขอบเวลาพอดี
    Lessonบทเรียน
    Fix the transport contract, not the business rule.แก้สัญญาการส่งข้อมูล ไม่ใช่กฎธุรกิจ
  • The 57-Second Ghostผี 57 วินาที Defeatedปราบแล้ว
    Symptomอาการ
    Bill creation felt slow, yet the endpoint everyone blamed answered in about 199 ms.การสร้างบิลช้า ทั้งที่ endpoint ที่ทุกคนสงสัยตอบภายในราว 199 ms
    Root causeต้นเหตุ
    Subtracting timestamps between log lines exposed a 57-second gap: a daily count plus lookups with no matching index.ลบ timestamp ระหว่างบรรทัด log จนเจอช่องว่าง 57 วินาที มาจากการนับรายวันและการ lookup ที่ไม่มี index รองรับ
    Fixวิธีแก้
    Indexes on the exact filter fields. No rewrite of business logic.เพิ่ม index ตรง field ที่ filter จริง ไม่ต้องเขียน logic ใหม่
    Lessonบทเรียน
    Measure the gaps between logs, not only the endpoint you suspect.วัดช่องว่างระหว่าง log ไม่ใช่วัดแค่ endpoint ที่สงสัย
  • The Webhook Jamคอขวด Webhook Defeatedปราบแล้ว
    Symptomอาการ
    A marketplace cancel never arrived. The queue held pending events, days old.คำสั่งยกเลิกจาก marketplace ไม่เคยมาถึง คิวค้างอยู่ event ค้างมาหลายวัน
    Root causeต้นเหตุ
    Poisoned retries with the same error kept winning the oldest-first claim, so nothing behind them moved.retry ที่ error ซ้ำเดิมชนะการหยิบแบบเก่าสุดก่อนทุกรอบ ของที่อยู่ข้างหลังเลยไม่ขยับ
    Fixวิธีแก้
    Fail-fast dead-letter for that error, a rate limiter, priority for cancels. Also caught a stale agent branch that would have deleted the existing dead-letter path.ส่ง error นั้นเข้า dead-letter ทันที ใส่ rate limiter และให้ cancel มาก่อน ระหว่างทางยังจับได้ว่า branch ของ agent ที่ล้าหลังจะลบ dead-letter เดิมทิ้ง
    Lessonบทเรียน
    One bad class of message can starve a whole queue.ข้อความเสียแค่ประเภทเดียวก็ทำให้ทั้งคิวอดตายได้
  • The Rate-Limit Cascadeน้ำตก Rate Limit Defeatedปราบแล้ว
    Symptomอาการ
    After a release, the marketplace answered 429, then the alerts about it hit the chat tool's own rate limit.หลัง release marketplace ตอบ 429 แล้ว alert ที่แจ้งเรื่องนี้ก็ไปชน rate limit ของแชทอีกทอด
    Root causeต้นเหตุ
    A correctness refactor turned a sequential cron concurrent, and every layer retried immediately.refactor เพื่อความถูกต้องทำให้ cron ที่เคยรันทีละตัวกลายเป็นรันพร้อมกัน และทุกชั้น retry ทันที
    Fixวิธีแก้
    Honour Retry-After, add a distributed lock, alert once after retries are exhausted.เคารพ Retry-After ใส่ distributed lock และ alert ครั้งเดียวหลัง retry หมด
    Lessonบทเรียน
    A correctness fix changes traffic shape. Compute peak QPS and retry amplification first.การแก้ความถูกต้องเปลี่ยนรูปทราฟฟิกได้ คำนวณ QPS สูงสุดและการขยายตัวของ retry ก่อน
  • The Lost BrokerBroker ที่หายไป Defeatedปราบแล้ว
    Symptomอาการ
    Orders stopped flowing for hours, while the sender's logs said "Completed".ออเดอร์หยุดไหลไป ชั่วโมง ทั้งที่ log ฝั่งส่งบอกว่า "Completed"
    Root causeต้นเหตุ
    The message broker restarted and the publisher had no reconnect. Proven with a normal day as baseline and neighbouring orders as a control group.message broker restart แต่ publisher ไม่มี reconnect พิสูจน์ด้วยการเทียบกับวันปกติและใช้ออเดอร์ข้างเคียงเป็นกลุ่มควบคุม
    Fixวิธีแก้

  • The RAM Thrash Golemโกเลมกิน RAM Defeatedปราบแล้ว
    Symptomอาการ
    A database host froze with no out-of-memory kill to explain it.เครื่อง database ค้าง โดยไม่มี OOM kill ให้เห็นเลย
    Root causeต้นเหตุ
    A swapless host running two uncapped database processes, thrashing under full-collection scans from a 5-minute cron (87% of all slow-query time) and a log collection with no TTL.เครื่องไม่มี swap รัน database 2 process ที่ไม่จำกัด cache โดน full-collection scan จาก cron ทุก 5 นาที (87% ของเวลา slow query ทั้งหมด) และ collection log ที่ไม่มี TTL
    Fixวิธีแก้
    11 indexes, an audit TTL, 30-day log retention and a live cache cap.index 11 ตัว, TTL ให้ audit, เก็บ log 30 วัน และจำกัด cache แบบ live
    Lessonบทเรียน
    Diagnostic reads are load too. Even the investigation's own count queries squeezed free RAM.query เพื่อวินิจฉัยก็เป็นโหลด แม้แต่ query นับของการสืบสวนเองก็บีบ RAM ที่เหลือ

  • The −7 Hour Shiftเวลาเพี้ยน −7 ชั่วโมง Defeatedปราบแล้ว
    Symptomอาการ
    Payment-slip orders were stored seven hours early.ออเดอร์ที่จ่ายด้วยสลิปถูกบันทึกเวลาเร็วไป 7 ชั่วโมง

    Lessonบทเรียน

  • The Number Thiefหัวขโมยเลขที่เอกสาร Defeatedปราบแล้ว
    Symptomอาการ
    After a data recovery, a running-number generator started reissuing numbers the ERP already held.หลังกู้ข้อมูล ตัวรันเลขเอกสารเริ่มออกเลขที่ ERP มีอยู่แล้วซ้ำ
    Root causeต้นเหตุ

    Lessonบทเรียน
    "The unique constraint didn't prevent the damage. It chose its shape.""unique constraint ไม่ได้กันความเสียหาย มันแค่เลือกรูปร่างของความเสียหาย"
